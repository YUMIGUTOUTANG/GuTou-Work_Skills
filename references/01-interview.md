# 01 · 反问摸底与候选人画像卡

目标：用最少的问题，摸清四件事——**目标方向、技术栈、背景类型、可用线索**。问题要像"帮你想项目的人"在问，不要像审讯。

## 首轮问题（一次给出，3~4 题）

> 每道题都给 2~3 个示例选项，用户可以直接抄、也可以自由回答。

### 问题 1：目标岗位方向

- 想找什么方向的工作？例如：
  - AI 应用 / 大模型应用开发
  - Agent 开发
  - AI 全栈（前后端 + 模型都碰）
  - 后端（偏 AI 或无明确 AI 要求）
- 有没有具体的目标公司、岗位名称或 JD 关键词？（有就一并说，会并入检索信号）

### 问题 2：技术栈盘点

- 主力语言与框架（Python / Java / Go / TypeScript / ……）
- 大模型工具链使用经验，例如：用过 LangChain / LlamaIndex / Dify / RAG 搭建 / 微调 / 推理部署……
- 每项给个熟练度：**做过完整项目 / 课程学过 / 只看过一点**

### 问题 3：背景类型（四选一）

- A. 有相关方向实习（AI / 大模型相关）
- B. 有实习，但方向不相关（传统后端、测试、数据等）
- C. 没有实习，但有实验室课题或导师项目
- D. 都没有——课设 / 自学 / 对某个行业感兴趣

### 问题 4（可选）：已有线索

- 有没有"想做一直没做"的东西？比如：一直想学 RAG、想碰 Agent 工作流、对某行业（医疗 / 金融 / 电商 / 教育……）熟悉？

## 追问规则

- 首轮之后最多追问 **1~2 轮**，每轮不超过 3 问；
- 只追问两类内容：
  1. **澄清矛盾或模糊**（"你说用过 RAG，是搭过完整链路还是只跑过 demo？"）
  2. **深挖可用素材**（"你的实验室课题具体做什么？有没有可以和 LLM 结合的部分？"）
- 不问用户专业判断（比如"你觉得什么项目算好项目"），不问可自行推断的信息；
- 用户已主动说过的信息不要重复问。

## 背景四分类 → 包装策略

| 背景 | 包装策略 |
| --- | --- |
| A 有相关实习 | 不要自我降级为"实习生"视角；从完整业务逻辑的高度来包装，让新项目与实习经历形成互补 |
| B 实习不相关 | 把手上业务场景与 AI 结合：传统业务 → RAG / Agent 改造叙事，本身就是差异化亮点 |
| C 无实习有实验室/课题 | 结合实验室方向（生物医药 / 金融 / 法律 / 泛工科……）找同领域开源项目，场景真实且稀缺 |
| D 无线索 | 结合手头可用的业务场景（语言能力、经济学背景、个人兴趣行业都可以），选一个能自圆其说的场景方向 |

配套原则（贯穿检索与写作）：

- 场景迁移时只换"场景与业务价值"表述，技术链路保持一套完整逻辑；
- 迁移前自问两题：① 该场景哪些数据外部拿不到？② 用户原来怎么解决问题、你怎么替代或加速？

## 输出：候选人画像卡（模板）

```markdown
## 候选人画像卡
- 目标方向：<方向 + 关键词>
- 技术栈：<语言/框架> + <LLM 工具链经验与熟练度>
- 背景分类：<A/B/C/D> → 包装策略：<对应策略一句话>
- 可用素材：<实验室课题 / 实习业务 / 兴趣行业 / 已有技能中可差异化的点>
- 建议项目类型：<从 02 的岗位族模板中选 1~3 个>
- 检索关键词草案：<5~8 个关键词 / 技术词>
```

## 定稿检查点（必须执行）

输出画像卡后，务必问一次：

> "以上是根据你的情况整理的小结。**还有什么要补充的吗？**（时间安排、偏好、不想碰的方向、指定技术栈、任何线索都可以说——没有的话我们就按这个去找项目。）"

用户确认（或补充后修正画像卡）再进入检索。补充的信息要实时更新进画像卡。
