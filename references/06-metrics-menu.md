# 06 · 指标菜单与数字纪律

## 数字纪律（五条，所有量化数字必须遵守）

1. **量级自洽**：数字量级必须与项目真实体量匹配（star 数、领域、代码规模）——小项目禁止写"日均千万级调用"；
2. **全文一致**：三个版本之间、概括句与细节之间，同一指标的数字必须完全一致，不得层层加码；
3. **口径清晰**：指标从下方菜单按项目类型选取；写法带上评估来源与口径（如"（测试集 800 条，LLM+人工双评）"）；
4. **跨度合理**：提升跨度控制在常见合理区间内（见下），禁止"10%→100%"这类一眼假的跨度；
5. **优先锚定真实数据**：仓库里有 benchmark / 规模 / 性能数据时，以真实数据为基准，再给出合理的优化后数值。

## 指标菜单（按项目类型）

| 类型 | 常用指标 | 写法示例（示例量级） |
| --- | --- | --- |
| 检索质量 | Recall@K / P@K / MRR / NDCG@K | "Top5 召回率从 65% 提升至 90%"；"Recall@10 从 53% 提升至 89%" |
| 问答 / 生成 | 回答准确率、解决率、多轮准确率、满意度 | "回答准确率从 54% 提升至 89%"；"多轮准确率从 35% 提升至 89.6%" |
| 微调 / 工具调用 | 函数选择准确率、参数 EM、整体调用准确率 | "函数选择准确率从 78% 提升至 86%"；"参数 EM 从 71% 提升至 83%" |
| 性能 | 延迟、吞吐 / QPS、推理加速比、显存占用 | "平均响应从 3.2s 降至 1.4s"；"检索延迟低于 100ms"；"显存需求降至消费级单卡（QLoRA）" |
| 规模 | 数据规模、样本规模、调用量、交互量 | "覆盖 5000+ 文档"；"构造 2000+ 训练样本（含 30% 负样本）" |
| 成本 | 调用成本下降、资源占用下降 | "单次问答成本较原方案下降 30%" |
| 业务 | 满意度、转化率、时间节省、覆盖提升 | "人工转接率下降 30%"；"培训准备时间缩短 40%" |

### 口径注意事项

- K 值要固定并写明（如 Recall@10、Top5）；
- 评测集规模、标注方式尽量写出来（"测试集 800 条""人工标注 200 条抽样"）；
- 弃用无意义指标撑场面（如机器翻译时代的 BLEU 小幅提升）；
- 同一指标不要在同一项目重复出现三次以上。

## 量级参考（无真实数据时可参考的合理性区间）

| 项目体量信号 | 建议量级 |
| --- | --- |
| 个人小项目 / 200 star 以下 | 调用量：月均千级~万级；数据规模：几十~几百份文档；并发：个位数~几十 |
| 中等活跃项目 / 200~5k star | 调用量：月均十万级；数据规模：千级文档；并发：数十~百级 |
| 较大影响力项目 / 5k+ star | 调用量：可写日均百万~千万级（与项目真实形态匹配）；规模：万级文档 / 样本 |

**使用规则**：以上是"不显假"的量级参考，可上下微调，但不要跨越两个数量级；有真实数据时永远以真实数据为准。

## 提升跨度参考（合理性校验）

- 检索 / 问答类：常见"30~65 → 85~95"区间（如 35%→89.6%、53%→89%、65%→90%）；
- 微调 / 工具调用类："70 级 → 85 级"（如 78%→86%、71%→83%）；
- 性能类：延迟"秒级 → 亚秒级 / 百毫秒级"、"分钟级 → 秒级"；
- 禁止：10%→100%、10%→99.9% 这类无过程支撑的极端跨度。

## 反面示例（禁止出现）

- ❌ "月均调用 8w+ 108 200-300"（无单位、无口径、数字杂乱）；
- ❌ "推动多源数据融合、问答准确率和稳定性全面提升"（无数字的空话）；
- ❌ "仅 BLEU +2%"（无意义指标撑场面）；
- ❌ 同一项目同一指标，精简版写 95%、详细版写 86%（不一致）。
