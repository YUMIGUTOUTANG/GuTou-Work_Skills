# 03 · 红海 / 套路项目排除清单

## 为什么要有这个清单

"人人都写的项目"在简历筛选与面试环节是**减分项**：面试官一天能见到十几个同款，项目越眼熟，"有区分度"的评价就越不可能出现。本清单用「特征规则 + 可维护示例」的方式，在检索评分时识别并规避红海项目。

## 排除信号（命中 ≥2 → 剔除；命中 1 → 标记红海风险并降权）

1. **教程 / 培训配套**：README 自述与付费或免费课程、培训班、系列教程配套（"课程源码""跟练项目""配套代码"等字样）；
2. **仿写练习类**：项目本体是对某知名系统的跟练复刻，名字多为"XX 商城""XX 管理系统""XX 秒杀""XX 云盘"等培训常用题材；
3. **求职导向标签**：自述为"简历项目""面试项目""毕设模板""学习项目"；
4. **教学流量特征**：被大量 fork 但 issue / PR 互动极少、更新主要发生在教程发布周期；
5. **模板批量复刻**：同一系列 / 同一作者按模板批量生成的细分领域项目（一眼同款）；
6. **旧而不活**：曾经广传于简历圈、但近一年无提交、无 issue 响应的"化石项目"。

## 豁免情况（不适用排除）

- 用户明确指定了这个方向 / 项目；
- 用户目标就是"给知名项目贡献 PR、拿贡献者身份"——此时大 star 项目优先，但要在短名单中说明"需要真贡献才成立"；
- 项目是领域事实标准（如推理服务化领域的主流框架）——注意区分用法：只"会用"区分度低，要给出"如何做出差异"的建议；能"改造 / 贡献"则是加分。

## 高区分度替代思路

- **垂直领域**（医疗 / 金融 / 法务 / 教育 / 工业……）× 真实业务场景；
- **活跃但不过度饱和**的项目：有社区、有 issue 流转，但还没到"人手一个"的程度；
- **能与用户背景结合**的项目（实验室方向、实习行业、个人兴趣领域）——背景本身就构成差异化。

## 维护说明

- 新增条目请提交 PR，只增加**特征化描述**，不点名攻击具体个人 / 机构 / 课程；
- 条目格式：`信号名称 —— 特征描述 —— 判定建议（剔除 / 降权）`；
- 定期清理：超过一年不再流行的信号可以合并或删除；
- 本清单为初版，由项目维护者根据公开招聘社区常见讨论整理，欢迎补充。
